## P1：发布阻断及正确性问题

### R01：安全修复与默认开发分支分离

范围：当前开发目录；生产当前暂停状态未被改变。

当前 Compose 的 worker/watcher 没有 `background` profile，缺少生产修复里的评审/全量扫描统一开关及额度防护实现。部署指引已按 `6d904e7` 编写，但当前 `main` 不具备同一契约。仅看 README 然后在默认分支执行 `docker compose up -d`，会启动后台服务，且可能丢失此前修复。

处理：由代码负责人先将生产修复与当前评分改动整合成一个经过测试的完整 SHA。CI 核对必需保护模块、默认关闭的开关、后台 profile 和 `.dockerignore`。禁止把“文档写了安全规则”当作代码已有保护。

证据：`docker-compose.yml`、`app/config.py` 与安全工作树同名文件；祖先检查结果。

### R02：缓存过期不等于数据刷新，软删除可能长期不更新

范围：两个版本均存在。证据：`app/metrics.py` 的 `_change_stamp`、`collected`；`app/audit_bridge.py` 的删除/恢复写入。

变更戳仅检查节点总行数、文档总行数、最大 `discovered_at`、活跃库数量。软删除、恢复、创建日期更正、上传人更正、主基线切换等原地变更未必改变这些值。TTL 到期后戳未变就直接续期，错误缓存可以长期保留。部分同步路径的进程内 `invalidate_cache()` 也不能使另一个 API 进程的缓存自动失效。

隔离 SQLite 复现：1 个有效文档首次聚合为 1；将 `is_deleted` 改成 true，提交并使缓存过期；`collected()` 仍为 1，而 `_collect()` 为 0。没有修改生产数据。

处理：使用事务内更新的聚合版本/数据修订号，包含删除、恢复、归属、日期和基线切换；跨进程共享版本。设强制重算最大间隔，避免旧值无限续期。展示统计更新时间和刷新失败状态。

### R03：同页面快速操作存在旧响应覆盖新状态

范围：两个版本均存在。证据：`static/app.js:161` 的 `renderTreeSection`、`renderOrgSection`、`renderOverviewTrend`。

现有 `navAbort` 只在切换整页时失效。连续筛选/年-月-日下钻仍复用同一个信号；回包仅检查卡片是否存在，没有请求代次或筛选快照校验。较慢的旧请求可覆盖后发请求，且渲染时读取已改变的 `state`，造成面包屑与数据范围不一致。

处理：每个区域独立 AbortController 和 generation；请求参数取不可变快照；只有最新代次能够提交 DOM/图表。非幂等操作提交期间禁用按钮。

### R05：治理写接口缺少角色授权，可覆盖其他知识库管理员

范围：两个版本均存在。证据：`app/main.py` 的 `patch_governance`、`enqueue_review`。

全局中间件只保证登录。治理 PATCH 没有 `require_admin` 或知识库角色检查，接收部门字段后删除该库全部 `WorkspaceRole` 再写入提交列表。普通登录用户可调用这些接口，并可用空角色列表清空治理角色。手动重评也没有明确角色限制，操作人使用默认 `actor()` 而非该请求的实际登录身份。

这是应用治理配置的写权限问题，不是钉钉文档写入。代码路径已确认；未对生产发送写请求。

处理：明确平台管理员/知识库管理员/审核员的权限矩阵；服务端逐库鉴权；组织归属只能引用 bi_center 权威结果，不能仅信任前端名称；操作审计保存真实 UnionID 和修改前后摘要。

### R06：评审入队不幂等，领取非原子，恢复没有任务租约

范围：两个版本均存在；生产当前无待处理/运行中评审，风险在启用或扩容后。

证据：`app/main.py` 的 `enqueue_review`；`app/service.py:260` 的 `process_next_job`、`sweep_stale_runs`。

每次重评请求生成新任务，没有请求幂等键/同文档在途去重，也没有队列容量上限。领取是先 SELECT pending 再 UPDATE running，不带行锁或条件更新；两个 worker 可能领取同一任务。启动恢复把所有 running 重置 pending，没有 owner/heartbeat/lease，扩容或重启另一实例可能把仍在正常执行的任务重新排队。

结果可能是重复正文下载、重复模型调用、重复评审实例和推送。实例不可变不代表任务执行幂等。

处理：原子领取、唯一请求键和有效租约；租约过期才恢复；暂停时拒绝或明确管理手动入队；队列容量/速率上限；结果、通知按任务唯一键防重。启用后台前模拟双 worker 和进程中断。

### R07：冷缓存缺单飞，聚合会在并发冷启动时重复执行

范围：两个版本均存在。证据：`app/metrics.py` 的 `_refresh_lock`、`collected`。

刷新锁只覆盖已有旧缓存的后台重算，首次 `_cache['value'] is None` 时各请求独立计算。冷启动聚合单次已测到约 3.68 秒；并发访问会重复相同的 SQL GROUP BY。TTL 边界还会并发执行变更戳 COUNT，再争抢后台锁。当前低 CPU 不能排除这个压力峰值。

处理：冷启动 single-flight、有界等待/预热；轻量共享版本戳；聚合结果或分层统计表；SQL 执行超时及观察指标。MySQL 不引入 Redis。

### R08：常规历史部门统计仍使用当前组织映射

范围：两个版本的常规 `org_rollup` 均存在；生产研发范围过滤已有月度组织缓存，但不能据此认为全部历史组织汇总已正确。

证据：`app/metrics.py` 的 `_employee_rows`、`_person`、`org_rollup`；`app/orgmap.py` 的 `ensure_employees`。

`EmployeeMap` 是当前缓存；身份补齐传入当前月，不是用户所选历史月。历史月份的上传统计随后按这个当前部门/业务组聚合。`matched` 但 `includeInOfficialStats=false` 的结果仍可能进入部门桶，未严格隔离为诊断。年度统计不能用某一个当前月份归属替代全年各月归属。

处理：消费 bi_center 对应月度快照，按 `(employeeKey, month)` 归属；正式统计必须同时 matched 与 include=true；缺历史快照时明确展示缺口，不能猜测或复制七部门判断。

### R12：后台资源边界不足，不应直接放开评审或横向扩容

范围：两个版本 Compose 均未设置 CPU/内存和 Docker 日志大小限制；PDF 解析两版本均在进程内运行。

证据：`docker-compose.yml`；`app/content.py` 的 `_pdf_text`；`requirements.txt`。

tmpfs 限制临时文件，不限制 Python 内存。PDF 先提取最多 100 页再截字符，没有独立进程硬超时/内存限制；复杂或异常文档可能长期占住 worker。当前开发中的 Office XML/单元格上限已经存在，不应误判成“所有格式都无上限”。依赖还有范围版本，不同时间构建不保证得到相同依赖。

处理：根据压测结果分配容器 CPU/内存、日志滚动及线程/队列并发；高风险解析用可终止子进程；锁定构建依赖、发布镜像 digest；OOM/DB 连接失败时保留任务和可诊断状态，不静默丢数据。

### R14：探测/全量脚本可以绕过生产调用保护

范围：脚本在两个版本都仍需治理；不能仅靠 API 容器开关保证无人直接运行历史脚本。

证据：`scripts/scan_uploader_baseline.py:52` 的直接 httpx 请求、`/wiki/nodes` 全量遍历；Dockerfile 复制整个 scripts 目录。

该脚本直接访问钉钉接口，没有经过新适配器的额度计数/熔断。关闭 watcher 或诊断计数为零，不等于脚本不会产生付费调用。错误摘要还拼接 `response.text`，可能引入不应写日志的上游数据。

处理：区分只读状态脚本、迁移、外部探测、全量扫描、数据清理和真实推送；付费调用统一接入保护模块；高成本/写入脚本不进入默认生产镜像，显式审批、预算、dry-run 和脱敏输出。禁止将历史运行命令当作日常巡检命令。

### R15：当前分支缺 `.dockerignore`，Git 忽略不保护构建上下文

范围：当前 `main`；生产安全修复版本已有 `.dockerignore`。

本地 runtime 有 68 个文件，合计 `135041308` 字节，包含 SQLite、扫描输出、临时 Python 和日志。它们已被 Git 忽略，但没有 Docker 忽略时仍可能进入发送给构建器的 context；`.env` 和 `.git` 同理。Dockerfile 未 COPY runtime，不代表这些内容从未交给构建器。

处理：先整合生产 `.dockerignore`；核对敏感目录、测试产物和开发工具排除；随后对生成文件分类。不能直接删除 runtime，其中数据库和扫描产物可能是唯一可用副本。

### R18：文档等元数据直接拼接 HTML，存在注入路径

范围：两个版本。证据：`static/app.js` 文档列表、文档详情、知识库列表将 `name/document_name` 等字段直接放入 `innerHTML`；链接直接拼入 `href`。

服务接收外部知识库元数据和历史导入数据，前端没有统一 HTML/属性转义或链接 scheme 校验。若数据含 HTML/事件属性或危险链接，可能影响查看者的页面与登录态下操作。本次只确认未转义的代码路径，未在生产投放载荷；是否已有恶意数据、上游是否限制特殊名称没有验证，不代表已发生攻击。

本次只修复了登录用户名称的渲染，不能据此认为业务列表均安全。后续使用 textContent/DOM 节点构造；必须拼模板时区分文本、属性和 URL 的处理；外链仅允许明确的 http/https 域名/路径策略，再验证 CSP，不能靠单一字符串替换解决所有上下文。

## P2：性能、可观测性和工程整理

### R04：总览趋势图重复绑定；部分失败显示为“无数据”

证据：`static/app.js:63` 的 `bindChartDrill`、`renderOverviewTrend`、`optional`。两个版本均存在。

总览月/日切换复用同一个图表 DOM 和实例，每次再绑定 ECharts 与 ZRender click，没有解除旧监听。反复下钻/回退后一次点击可能执行多个旧回调。增量卡片通常重建 DOM，不能据此把每次卡片刷新都断言为同一种监听泄漏。

`optional(...,{items:[]})` 又将部分非 Abort 错误吞成空数据，用户会看到“无数据”而不是接口异常。

处理：图表绑定前解除本模块旧 handler；显式显示失败、重试和数据时间，不用空数组伪装成功。

### R09：healthy 只证明进程能回答 HTTP，不证明数据服务可用

证据：`app/main.py` 的 `health`，Compose 的 healthcheck。两个版本均存在。

`/api/health` 返回常量，不查询数据库、不验证后台心跳。运行后数据库断连，容器仍可能 healthy，而登录/业务请求失败。没有容器数据库故障、磁盘不足、恢复后事件重放的本次演练记录。

处理：保留轻量 liveness，增加带短超时的 DB readiness；API 和后台分别检查；告警关注错误率、连接池等待、队列年龄、最后成功同步/评审时间。按部署指引完成备份恢复演练，明确 RPO/RTO。

### R10：列表存在 N+1 与深分页增长问题

证据：`app/main.py` 的 `documents`、`files_unified`；两个版本均存在。

旧 `/api/v1/documents` 最多取 200 文档，每条再查一次最新评审、一次评审数量，最多约 401 条业务 SQL，尚未计会话查询。新统一文件列表第一页本次较快，但混合两来源时取 `2 × (offset+limit)` 行到 Python 再排序；offset 没有上限。获取本页最新评审时又读入本页文档的全部评审历史。

处理：最新评审和计数用批量/window 查询，保留不可变历史；混合列表采用稳定游标/数据库合并分页；为 `(node_id, created_at)` 等实际查询设计并验证复合索引，检查 EXPLAIN 后再上线，不盲目加索引。

### R11：页面 GET 会同步解析组织身份，外部故障拖慢页面

证据：`app/main.py` 的组织/上传人 GET；`app/orgmap.py:35`；两个版本均存在。

组织 GET 最多补 500 人，50 人一批，逐批外部 HTTP（单次配置 15 秒超时）和间歇暂停。超时异常仅 continue，失败身份没有短期负缓存/退避，下一次页面访问可再次补齐。15 秒不是整个请求的总时限，不能当作端到端 SLA。

处理：GET 仅返回已就绪缓存及状态；补齐任务有界后台执行，失败退避、总时限、并发上限；缺失归属进入诊断，不使界面阻塞或猜测身份。

### R13：旧规划与当前强约束冲突，脚本没有风险索引

原先 docs 下 6 篇平铺文档，没有统一 docs 索引。AGENTS 要求先读一期规划，但该规划仍出现 Redis、`39057`、POC/待冻结决策，与当前无 Redis、外部 MySQL、`39021`、已上线状态不一致。README 虽提示暂停，后文仍有历史“实时镜像”运行叙述，且旧本地演示命令可能误启动全部后台。

本次新增 `docs/README.md`，将当前约束、部署、契约、业务口径、历史规划与 Review 分组；未移动/删除旧文件，也未擅自改变 AGENTS 的必读要求。迁移与探测脚本仍没有完整安全索引。

后续整理方案：

1. `docs/architecture/current.md` 只描述当前实现；`docs/runbooks/` 放运维；`docs/contracts/` 放接口；`docs/archive/` 保留带“已取代/禁止实施”标识的旧规划与决策。移动前修复所有引用。
