## 实现

- 数字表头与单元格统一右对齐；顶部登记数由独立的认证后本地状态接口加载，不再依赖访问总览。登记数、本轮成功、未完成与失败分别表达；本轮任务限定当前recovery，未完成包含pending/running/dead_letter。全局提示评审/通知/全量暂停，历史403不再冒充当前权限结论，诊断异常和通知时间均显示北京时间。
- 新接口只读Workspace小表、当月ScanCycle和本轮ScanTask聚合，不外呼、不触发补采、不进入业务读缓存。状态失败可单独重试；全局请求不受页面路由取消影响，未登录仍被认证中间件拦截。
- 钉钉api/oapi在HTTP request hook统一平滑限速5QPS，所有角色共用同宿主目录和应用哈希锁文件。发送间隔至少200ms，取消不预订未来槽位，进程退出释放锁；状态不可用停止外呼，增量不消耗重试次数。限速不写MySQL，不影响BI或模型域名。日/月调用原子计数保留且不清零；搜索日预算500→2000、月预算仍10000。
- 新接收元数据在首次入库时核对源时间24小时资格，一次写入retry_started_at。合格远程事件等待额度不再滚动过期；重叠拉取不续期、不重开终态，实际失败仍最多3次。本地未确证删除/恢复仍保留48小时等待期限。第三次预约后退出的未处理记录，每片最多100条归为可观察的中断死信，不能永久挂起。
- 一次补偿使用固定UUID、明确的近7天以内时间范围、冻结ID上界、每片100候选升序游标；在SQL LIMIT前排除范围外、成功、忽略和非知识库流水。补偿批次和不可变明细两小表保留原次数/原因/冷却，一事件只能获得一次新3次授权。worker与准备命令共用桥接文件锁；先提交资格及游标再执行正常定位，重启接续，不扫documents/historical_file_nodes。
- 节点水位为第三张小表，按node主键保存本地删/恢复的源时间，观察时刻为DATETIME(6)，与已有Document时钟精度一致。延迟的删→恢复及逆序重放按源顺序处理；远程/目录新观察成为基线，旧补偿不得覆盖更新的删除状态。不改变原文档时间字段。
