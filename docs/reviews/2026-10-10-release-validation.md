## HTTP 压测与查询优化

请求先进行服务端会话验证。工具创建十分钟有效的合成只读会话，结束删除；不调用 OAuth、钉钉、模型或 bi_center，不输出凭据。12 条接口覆盖总览、年月日/研发增量、组织、文档、知识库、评分和筛选项。

| 场景 | 请求/负载 | p50 | p95 | p99 | 错误 |
| --- | --- | --- | --- | --- | --- |
| 初轮缓存 | 1,200；40 req/s；20 并发上限 | 3.67ms | 6.04ms | 9.74ms | 0 |
| 高负载 | 6,000；100 req/s；50 并发上限 | 4.83ms | 46.52ms | 180.78ms | 0 |
| 库存差异缓存后 | 1,200；40 req/s；20 并发上限 | 3.03ms | 4.22ms | 5.03ms | 0 |
| 最终功能版隔离验收 | 6,000；100 req/s；50 并发上限 | 4.26ms | 27.71ms | 110.27ms | 0 |
| 生产部署后 | 1,200；40 req/s；20 并发上限 | 3.68ms | 5.42ms | 10.15ms | 0 |

这是服务器 loopback HTTP 延时，含会话验证，不是公网首屏/渲染时间或 50 个实际用户。并发值是连接/在途上限。

冷文件首屏曾为 1.43 秒，仅加索引仍反复对照十多万条基线。新增基线独有 ID（129 个）及总数缓存、窄 SQL 分页后，`77ca679` 的新响应键 `limit=45` 首次请求 **85.66ms**、200；后续 50 请求 p95 8.36ms。库存源已预热，不能将其称为全部缓存/数据库全冷。

资源采样最大一次 API 内存 140.6MiB、CPU 57.8%（Docker 单核为 100%，限额 2 CPU）；不是连续监测，不能视为严格峰值。容器 768MiB/2 CPU/128 PID，连接池与刷新队列有界。
